# Active and pixel evidence packaging gates

The packager calls the full read-only `v2_active_gpu_results.validate_bundle(root)` when an active GPU amendment exists: after the plan's completion gates, before any migration receipt/destination or payload mutation, and during final-manifest evidence refresh. The returned validation must pass without errors. This delegates fixed-amendment semantics, active90GPU+486frozen inventory, separate72CPU/219-file reference history, descriptive roles and statistical-reference binding to the actual active validator. No table or CI is recomputed by this packaging gate.

The plan records only a small binding of amendment/audit/analysis/code and active/reference inventory SHAs, role and model counts. It does not duplicate the full active report. Assembly reconstructs the plan, compares that binding and checks it again before movement. The final folder preserves all relative paths; the same validator therefore checks the moved active data/results and CPU references at the destination root. The original CPU checkpoint remains a reference artifact and is not relabeled as a GPU checkpoint.

The pixel auditor excludes OS mutex markers from its scientific artifact map but still requires their one-byte `0` contents when loading a delivered bundle. The packager explicitly copies exactly the marker paths listed by `excluded_history_mutex_files`. Only the pixel admission guard and per-generation budget/stop guards may use the special `pixel_audited_mutex_marker` origin. Every marker must be a regular, nonredirected file of exactly one byte with contents `b"0"`. Duplicates, other paths, different bytes, MOVE, relabeled operations and omissions fail before payload migration. These copies are included in the normal manifest and are immutable during refresh. No marker is synthesized, edited or used to bypass a live-process check.

The scientific pixel bundle and every marker are checked again against package operations before mutation and against the previous manifest after delivery. CUDA evidence continues to use its existing exact MOVE inventory; its excluded guards have a different verifier contract and are not added by this change. Nested publication figures and CPU reference MOVE handling are otherwise unchanged.

Migration capacity accounting is unchanged: every actual COPY, new metadata write and ledger append charges its bytes before writing; same-root MOVE adds zero logical bytes. Admission checks do not consume the allowance. The migration budget's own start/finish scans total two. The existing completed ledger event also obtains a separate whole-root byte observation, so the entire packager performs an additional scan. Quiescence of all external writers remains a prerequisite. The packager does not claim protection against arbitrary concurrent external writes.

`test_v2_package_integrity.py` uses temporary byte fixtures and explicit mocks for full scientific validators. It tests refusal propagation at all three active gates, stable active-plan binding, marker scope/content/operation constraints, and real fixture COPY/ledger/manifest/capacity behavior. These fixtures certify packaging mechanics, not scientific results or actual release readiness. No real plan, migration, model score, manuscript or experiment is produced by the tests.
