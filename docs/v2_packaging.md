# V2 author-review packaging

`code/v2_package_delivery.py` plans a standalone directory at `delivery/RemoteSensing_GeographicSelection_V2`. It preserves project-relative paths so the delivered `code/v2_reproduce.py --root TARGET` executes the delivered frozen code. Packaging is a final author-review step, not a submission-ready claim, publication action, upload or license grant. Unknown author metadata may remain for the author to resolve.

## Plan first; assemble only after writers stop

```text
python -B code/v2_package_delivery.py --plan
```

The default mode writes only `evidence/v2/package_plan.json`. It checks the final gates, records source/target relative paths, COPY/MOVE operations, every file's size/SHA256, additional COPY bytes, zero-growth MOVE bytes and a conservative metadata reservation. It separately reserves `max(size of the six numerical files) + 4,000,000` bytes for actual independent delivery reproduction. The plan's combined peak includes COPY, packaging metadata and that reproduction peak under the entire source-project cap, strictly less than2,000,000,000 logical bytes including the retained V1 directory, ZIP and runtime; hard links count at every path. Capacity is checked again during assembly and after completion. No links are created. A blocked or over-budget plan does not authorize assembly or automatically reclaim space. Before all gates pass, the plan records the missing prerequisites and marks its storage estimate incomplete; it does not inspect partial model-result JSON.

Required gates are a passed exact576-run completeness audit, a passed72-image/24-region checkpoint reload, an actual passed tables reproduction with unchanged six numerical outputs, nonempty final `paper/v2/manuscript.docx`, `manuscript.pdf`, `supplementary_material.docx`, `supplementary_material.pdf` and `manuscript_source.json`, and `evidence/v2/research_review.json` with `passed: true` plus `release_recommendation: AUTHOR_REVIEW_PACKAGE`. DOCX/PDF signatures are checked. The53 frozen dependencies and current audited input/artifact/result hashes must still match. Reproduction and reload must bind to the current freeze and reproduction to the current audit/results. These are integrity/release gates; they do not infer scientific contribution from a positive metric.

The scientific review must additionally contain `checked_file_sha256`, a map of project-relative POSIX paths to SHA256 values. It must cover all five manuscript artifacts above and all six files in `NUMERICAL` (`conditions_by_source.csv`, `conditions.csv`, `regions.csv`, `classes.csv`, `contrasts.json`, `primary.json` under `tables/v2/`). Every required and additional checked file is verified against current bytes; missing, unknown, redirecting or escaping paths fail. Thus an old review cannot approve a subsequently edited manuscript or number table. Additional reviewed artifacts must fit the allowed small-file inventory and are copied if not already included. Refresh applies the same version-binding gate.

Only after the scientific review and all source training, analysis and document writers have stopped, the parent agent/maintainer may invoke under the existing user authorization to organize the delivery:

```text
python -B code/v2_package_delivery.py --assemble --confirm-no-writers
```

The flag is an internal consistency assertion made by the parent after checking the execution sessions have terminated; it does not require additional user approval. This utility cannot reliably discover every Python/editor process that might still write. Neither this flag nor `--assemble` bypasses any scientific/completion gate or permits assembly while the matrix is still running. The utility rechecks the saved plan, gates and hashes immediately before any mutation. The destination must not exist, and a prior completed source migration receipt blocks another migration. An unresolved preparation lock/temporary also stops execution. `--destination` may select another new V2-named directory directly under `delivery/`; the reviewed plan fixes the actual destination. `--assemble` executes that saved destination and extras, not a newly supplied replacement path.

## What moves and what copies

- **MOVE:** only the192 manifest's RGB/label/metadata files plus the known top-level data manifest/selection-plan files (`manifest.json`, `development_manifest.json`, `old_development_manifest.json`, `selection_plan.json`, `selection_plan_old.json` when present), preserving their relative structure; each audited576 `result.json`; each result's referenced SHA-verified log; the single predetermined checkpoint. Unreferenced data extras appear in `plan.excluded` and remain at source. Moves use same-project rename with no cross-device COPY fallback. Empty source directories can remain; they are not deleted automatically.
- **COPY:** the53 frozen dependencies not already moved; the original manifest metadata referenced by the data audit; original/new-panel feature **index JSON metadata**; freeze; the reproduction and packaging entry points; V2 documentation and related attribution/reference files; top-level publication assets under `tables/v2/`, `paper/v2/`, `figures/v2/`; root V2 text reports; calibration/software/source-snapshot/audit-attempt/prospective-amendment text evidence; and `manuscript_state.json`.
- **MOVE, exact feature-cache exception:** the120 NPZ files listed by frozen `cache/dinov2-formal120/index.json` and72 listed by frozen `v2/cache/new_panel_dinov2/index.json`, preserving those relative paths. The default ready plan requires all192 files and verifies their bytes against each index's `cache_sha256`, unique IDs/paths, flat `ID.npz` filenames, role membership and compact-manifest source bindings. Both index files and the compact manifest must match the53-file freeze; the inventory records the current freeze SHA and index SHAs. Missing/mutated files, duplicate identities, escaping filenames, redirected paths or unlisted NPZ anywhere under either exact formal cache directory block planning. These are same-project renames, never extra cache copies. The frozen index JSON bytes are copied unchanged as above.
- **RETAIN AT SOURCE:** the historical V1 delivery directory and ZIP, original TIFFs, runtime/dependency trees, unrelated caches, old V1 paper/figures, and unreferenced run pending/failure/history files. Nothing in these categories is deleted. The cache exception does not traverse or admit other cache directories, V1 arrays or arbitrary extra NPZ files. If a history record is already referenced by a frozen dependency it is copied; otherwise it remains available at the original source root.

`--include relative/path` adds a clearly named small-file extra, subject to the same exclusions. It cannot include V1 deliveries, old-paper paths, raw TIFFs, feature arrays, archives or runtime trees. Nested publication assets that the final source needs should be added explicitly or already be a frozen dependency; the plan intentionally does not sweep arbitrary subdirectories. Review `paper/v2/manuscript_source.json` for such dependencies before assembly. `docs/v2_venue_submission.md` is automatically selected by the V2 documentation naming rule when it exists.

Feature retention preserves the120 source caches containing native-resolution-mask-derived soft targets and the72 panel evaluation-feature caches. It does not reconstruct source targets from the448 PNG masks. The plan and write-ahead MOVE receipts include every selected NPZ size/SHA, and all192 references are checked again before any migration starts. Their bytes add zero to whole-project logical storage; only COPY files and metadata add bytes. Every writer, including feature/head processes, must be terminal before real assembly. This software change is preparation only: it does not claim an assembled delivery, a completed576-run audit or validated full refitting. Default NumPy-only tables reproduction does not load these arrays. Cached-head refitting and original feature regeneration have separate dependencies described in the reproduction guide.

All source and target ancestors are checked for symbolic links, junctions and Windows name-surrogate reparse points before resolution or I/O; redirected paths are rejected. Non-path-substituting OneDrive cloud placeholder tags are allowed. The protected-scope rules are applied again to the resolved project-relative source and destination names, so a file apparently named `v2/data/example.png` cannot rename a V1 PDF or original TIFF through a path alias. All sources and targets stay absolutely within the selected project; each target also stays inside the new delivery. Conflicting/duplicate targets, changed source hashes, unsafe paths and already existing output files fail. The plan copies small evidence before moving large data. COPY temporarily adds bytes; MOVE preserves the project's logical data volume. The reservation covers plan snapshots, write-ahead receipts, delivered receipt, README, complete manifest and working metadata. Capacity is checked again on each write. Disk-full/filesystem errors stop with the evidence already present.

## Migration receipts and interruption recovery

Before the first data move, a unique immutable plan snapshot and append-only JSONL ledger are created under `evidence/v2/package_receipts/`. Each operation is written and synced before execution, then its destination size/SHA is verified and committed to the ledger. A hard kill between rename and commit is recoverable by comparing both locations with the planned hash. Partial COPY files are retained for inspection. The tool never deletes a partial directory, automatically rolls back, overwrites an existing destination or guesses how to resume.

```text
python -B code/v2_package_delivery.py --status evidence/v2/package_receipts/ATTEMPT.jsonl
```

This prints the planned source/target locations, existence and SHA-match status without moving anything. Manual recovery must first verify all writers have stopped and inspect this receipt; rerunning `--assemble` against an existing destination is intentionally refused. The original project-wide plan may later change, but the attempt's hashed snapshot remains the recovery reference. Keep the source project until the final delivery has passed independent reproduction and the author has reviewed migration receipts.

The delivered `README.md` says that the active V2 data/results root has migrated. `evidence/v2/migration_receipt.json` at the source records the new root, ledger and final delivery-manifest SHA; it does not change the original top-level README. The parent/author can update that README separately after successful migration. Use the destination for subsequent V2 reproduction, because source-relative V2 data/result paths will have moved.

`delivery_manifest.json` covers every delivered file except itself, including the generated README and `evidence/v2/package_migration_receipt.jsonl`. The delivered receipt is the payload-completed ledger snapshot. The source ledger adds the final manifest SHA afterward, avoiding a circular receipt/manifest hash. Packaging receipts and source plans are excluded from the ordinary COPY inventory to prevent recursive packaging.

The manifest is initially a snapshot at assembly completion. Running reproduction inside the delivery legitimately changes timestamp-bearing operational reports, while the six numerical outputs must remain unchanged. After independent delivery reproduction, the parent can explicitly refresh the inventory:

```text
python -B code/v2_package_delivery.py --refresh-manifest
```

This command runs at the source project root and uses the source migration receipt/ledger to identify the assembled target. It never invokes reproduction automatically. Only `evidence/v2/run_completeness.json`, `tables/v2/analysis_identity.json`, `evidence/v2/reproduction_check.json` and optional-reload `evidence/v2/checkpoint_reload.json` may differ from the previous manifest. Every other existing entry must have identical size/SHA, including all six numerical files, paper, code, configs, data, results, logs and the delivered migration-receipt snapshot. Missing or unexpected files are refused.

Before accepting even those four changes, refresh requires the current passed reproduction, exact576 audit/analysis identities and count matrices, unchanged numerical hashes, current53-file freeze and current reload/review/manuscript gates. The prior manifest is backed up under the source `package_receipts/`; its SHA is retained in the new manifest and source receipt lineage. The source ledger appends the latest manifest SHA/time. The delivered receipt snapshot remains unchanged and covered by the new manifest, so no circular hash or newly introduced verification report is needed inside the bundle. Interrupted refresh temporaries and partially advanced receipts are retained for manual examination rather than repaired automatically.

## Checks performed while developing the tool

```text
python -B code/v2_package_delivery.py --help
python -B code/v2_package_delivery.py --self-test
```

Fixtures use only small, explicitly synthetic files in automatically removed OS temporary roots. They exercise cap rejection, safe boundaries, V1/raw/cache exclusions, duplicate-plan-target and existing-destination refusal, retained pending/V1 evidence, MOVE content SHA preservation, recovery receipts and the complete manifest excluding itself. An additional isolated refresh-policy test stubs the full scientific evidence verifier to test allowed operational changes, unchanged receipt snapshots, previous-SHA lineage, and rejection of numeric/code drift or unexpected inventory. The public CLI always requires the real complete576 evidence verifier; the policy-test stub is not a runtime mode. Tests do not assemble the real project, read partial model scores, run the scientific matrix/reload or modify frozen inputs. A software check does not certify final package content or scientific review completion.

Safety regressions additionally cover a192-record compact-inventory fixture leaving unreferenced extras at source; stale manuscript/numerical review hashes; unknown/escaping review paths; mocked name-surrogate rejection versus allowed cloud tags; and real temporary symlink/junction aliases to protected V1 content when the platform permits their creation. Unsupported link creation is explicitly skipped rather than claimed as tested. The reproduction utility separately tests a1,995MB parent policy with a150MB target, rejecting a6MB work peak that target-only accounting would miss.

Feature-specific fixtures cover exact120+72 frozen-index references; mutated/missing bytes; duplicate IDs and cache paths; traversal/absolute filenames; stale index SHA; inconsistent source SHA; unlisted NPZ; unsupported arbitrary-cache inclusion; and MOVE-only accounting with retained protected V1/ZIP/raw/unrelated-cache bytes. A synthetic migration checks every delivered cache SHA, frozen index bytes and receipts while accounting for the entire storage increase as small-file COPY plus generated metadata. Synthetic bytes test inventory and migration policy, not NPZ array semantics or scientific fitting.
