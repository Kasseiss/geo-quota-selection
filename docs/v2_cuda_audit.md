# Independent CUDA90 audit and descriptive analysis

`code/v2_audit_cuda.py` uses Python standard-library facilities and NumPy. It imports existing numerical/path/PID helpers without importing Torch, torchvision, CuPy, Pillow or model objects. It does not fit, reload models, stop processes, repair evidence or change the original576-fit primary analysis. Run it only after the fixed90 CUDA fits and all CUDA writer/child processes have terminated:

```text
python -B code/v2_audit_cuda.py --root PROJECT_ROOT
python -B code/v2_audit_cuda.py --root PROJECT_ROOT --audit-only
```

The locked plan must have SHA256 `15d586fd03389d495dfc2b7d9cdea35b2b3089461ccb49cc37e5f8bd39ff1545`. The auditor first checks writer/per-fit locks, actual PID creation identities, terminal worker leases and closed generations. Any unresolved writer lock, live/unknown child or unclosed generation refuses full audit. It then enumerates exact90 planned result paths. Missing or extra files refuse inspection of partial result scores. Next, a separate terminal-metadata pass parses all90 JSON files and checks only format, complete status, plan SHA, exact identity and source-selection metadata. A late malformed/nonterminal/mismatched result stops here, before training/log/CM validation, with `score_fields_opened: false` and no returned results. JSON parsing reads the file bytes; this does not mean numerical fields were inspected. Each file is SHA-bound during this pass, and the numerical pass requires these same bytes. Only after every header passes are numerical fields permitted. Formal analysis is generated only after all90 pass the complete audit. Existing CPU-primary work is separate; this gate concerns the CUDA execution writers.

The audit path is `evidence/v2/cuda_execution_audit.json`. The schema includes `format: v2-cuda90-audit-1`, `passed`, `expected_count`, `observed_count`, `validated_count`, `terminal_metadata_preflight_passed`, `terminal_metadata_sha256`, `result_files` (project-relative path to SHA256), `artifact_sha256` (raw logs, attempt starts and referenced parallel amendment/closed/worker leases), `code_sha256`, `inputs`, `provenance_by_result`, errors/missing/extra/duplicates and quiescence evidence. Before inventory enumeration, observed_count remains its initial0 if an active writer already caused refusal. A failed audit produces no new descriptive analysis; a pre-existing analysis is not silently deleted or presented as current. Always verify its current audit SHA.

The auditor verifies the original53-file freeze and current input hashes, scalar/preflight identities, complete192 compact identities and all PNG/sidecar byte hashes without decoding pixels. The CUDA plan must match the90 full-model identities in the original paired matrix. Every run must match its source-selected12 IDs, source-only CPU-calibrated encoder/decoder LR and steps, seed, CUDA device/runtime metadata, threads2, batch2, crop224, pretrained/model hash, selected-record hash, finite-parameter declaration and initial/final state-hash syntax. CUDA allocated/reserved memory and timing must be finite/valid. No CPU fallback or extra checkpoint is accepted as a substitute.

Each result's raw-log SHA/path, attempt-start identity/device/provenance, exact raw/history log equality, finite loss and monotone elapsed times are verified. The frozen fit logs step1, every50 and the final step. The audit requires all those expected sampled points exactly once and in order. It cannot demonstrate continuity of every unrecorded optimizer step. Similarly, CUDA learned states were not saved: valid state hashes and finite flags are checked declarations, not independent state reload or rehash evidence.

Both72 panel and20 source-validation per-image confusion matrices require exact ID/region membership, bounded integer8-by8 matrices, each class's truth margin equal to the data audit's SHA-bound actual448-mask histogram, cross-fit consistency and exact recomputation of aggregate metrics. This prevents a matrix with the same total valid pixels but altered true-class counts from passing. Saved aggregate score fields are never used as the source of the analysis; they must equal recomputation from verified matrices.

Scalar, V1-parallel and V2-parallel provenance remains distinct. Parallel results must bind their own immutable executor file/hash, original generation amendment, runtime, modulo ownership, authorized PID, terminal worker lease and closed global lease. Old V1 results are not required to match the current V2 executor hash. The audit checks the corresponding original bytes and never relabels or rewrites completed results. Attempt-start provenance prevents a parallel record from being silently relabelled as scalar.

The separate output `tables/v2_cuda/descriptive_analysis.json` has `format: v2-cuda90-descriptive-1`, `scope: DESCRIPTIVE_SECONDARY_EXECUTION_REPLICATION`, `audit_sha256`, exact audited `result_files`, `inputs`, `code_sha256`, expected/validated90, `original_primary_unchanged: true` and `new_independent_holdout: false`. It reports only four fixed union-class regional-mIoU contrasts: geographic k-center minus ordinary k-center; geographic k-center minus permuted geographic k-center; region-weighted facility location minus ordinary facility location; and region-weighted minus permuted-weighted facility location.

The original frozen `average_regional` and `paired_region_summary` functions define the analysis. Overall24-region differences first average three source allocations and three paired selection/optimization seeds within each region. Source-specific descriptions average their three paired seeds first, retaining the same24 geographic units. Paired percentile region-bootstrap intervals use the original10,000 repetitions and seed2026101805; leave-one-region-out summaries are inherited from that function. All contrasts, source strata and intervals are descriptive after prior use of the panel. There is no p-value screening, additional confirmatory claim, equivalence conclusion or selection of a preferred execution backend. This tool does not add an unplanned country grouping or select regions based on outcomes.

Audit and analysis retain complete input/result/code SHA maps. Inputs, artifacts, results and code are rehashed and quiescence/inventory rechecked before audit can pass. The final tables stay outside the execution-result tree to avoid recursive inventories. Report writes check the whole selected project against2,000,000,000 logical bytes with4MB working space. Atomic temporary reports are preserved if writing fails; scientific data/results are never overwritten by this tool.

```text
python -B code/v2_audit_cuda.py --self-test
```

The helper builds explicitly synthetic192-image/90-result evidence in OS temporary directories, with tiny stand-in byte files and known integer matrices. Its five test groups cover complete audit/fixed analysis, missing/extra inventory and live refusal, training/log/CM corruption, scalar/V1/V2 provenance, and a late90th malformed JSON/noncomplete status/wrong identity/selection/plan/format. The latter cases assert that CM validation was never called, the numerical gate remains closed, validated_count is0 and returned results are empty. It checks that Torch/CuPy were not imported. These checks do not read the incomplete real run matrix or certify completed real scientific results. The software record is `evidence/v2/software/cuda_audit_validation.json`; its earlier four-test record remains in development history.
