# Recorded V2 environment and reproduction scope

This describes the existing research setup, not a tested fresh installation. `evidence/v2/environment_record.json` distinguishes interpreter-visible metadata from packages in project-isolated `runtime/site-packages`; the latter directory is not bundled in the delivery. A previous metadata probe incorrectly assumed all packages were interpreter-visible and stopped at pyproj; the corrected recorder inspects both locations and does not claim they are interchangeable environments.

- Table reproduction uses Python3.13.13 and NumPy2.5.1. `docs/v2_requirements_tables.txt` records this minimal numerical dependency. The frozen auditor recomputes selection and validates SHA-bound mask-count evidence without reopening image pixels. Torch, CUDA, CuPy, Pillow and NPZ features are not needed for this path.
- Optional checkpoint reload additionally uses the existing PyTorch2.13.0+cpu, torchvision0.28.0 and Pillow12.2.0. Distribution metadata reports torch2.13.0, while the imported CPU build/calibration identity includes `+cpu`; both observations are retained. Reload reconstructs the model without downloading official pretrained weights and fixes CPU threads to8.
- Full spatial training uses that CPU PyTorch environment with8 threads. DINOv2 features were computed on CPU; their MLP heads use CuPy14.2.0 on the RTX4060 Laptop8GB. The earlier observed CuPy runtime12090 and NVIDIA driver13020 are retained with their source identity, rather than presented as a new GPU probe. System CUDA12.6 alone is not a full specification of the isolated CUDA libraries and Windows ASCII-path helper used here. No A100 training is claimed.
- Actual result plotting uses matplotlib3.11.0 in the research interpreter. Its software test used synthetic summaries only; complete audited results and visual inspection are still needed for the actual figures.

The planned delivery excludes Python/CUDA runtimes, original native TIFFs, unrelated caches and575 of the576 trained states. It now includes the exact192 SHA-bound NPZ caches listed by the frozen formal120 and new-panel72 indexes, in addition to compact images, source identities, all result/log records, frozen execution/analysis code and the single predetermined checkpoint. These are120 source caches with native-mask-derived soft targets and72 panel evaluation-feature caches. They are planned same-project MOVEs after all writers stop, with no cache copies or logical-storage growth; actual final inventory remains to be verified after fitting and assembly. Their retention preserves the original source targets and removes cache regeneration from a future cached-head refit's prerequisites. Default table reproduction remains NumPy-only and needs none of these arrays.

A separate cached-head refit needs the frozen runner, NumPy/PyTorch/Pillow and compatible CuPy/CUDA/NVIDIA settings; DINO weights are unnecessary when the SHA-verified extracted caches are reused. Original feature regeneration instead needs native source masks/RGB and the official SHA-bound DINOv2 weights/extractor environment. Full spatial refitting also needs official pretrained ResNet18 weights and the recorded CPU PyTorch environment. Compact nearest-resampled masks cannot replace native-mask soft targets. No clean-install, cached-head or actual576-refit validation is claimed here. Read `docs/v2_reproduction_guide.md` before arranging a refit in a separate workspace.

The environment recorder is a preparation utility, not part of default reproduction. Running it inside a final package would intentionally update a record and should not be confused with a byte-preserving verification. Actual numerical-table and checkpoint reproduction must pass from the final delivery directory before release; this ledger does not certify that pending step.
