# CUDA90 extension for the final V2 delivery inventory

`code/v2_cuda_delivery_inventory.py` is a read-only whitelist builder. It does not run training, compute scores, migrate files or amend the existing packaging tool. Call `build_inventory(root)` after the complete CUDA90 audit and descriptive analysis have passed and all CUDA processes are terminal. Its default CLI prints the inventory to standard output; it writes no report or cache.

## Required payload and authority

The exact SHA-pinned original90 CUDA plan fixes the run-directory identities. The helper requires `evidence/v2/cuda_execution_audit.json` with format `v2-cuda90-audit-1`, passed=true, expected/observed/validated counts90, no missing/extra/duplicate/error entries, exactly90 planned result paths, and current `result_files`, `artifact_sha256`, `code_sha256` and `inputs` SHA maps. The scientific auditor, rather than this delivery helper, validates training recipes and confusion matrices. This helper hashes result bytes without parsing their score fields.

`tables/v2_cuda/descriptive_analysis.json` must have format `v2-cuda90-descriptive-1`, bind the current audit SHA and the same result/input/code maps, and retain the descriptive secondary execution scope, unchanged original primary and no-new-independent-holdout declarations. The original576 primary remains separate.

The whitelist covers every recognized text file in every planned CUDA run directory: final result, all raw training logs, attempt records, failures, closed/recovered per-fit claims. It also covers every closed parallel generation: amendment, supervisor/worker summaries, closed global lease, terminal child leases, raw worker stdout, start/stop and budget metadata. Scalar/V1/V2 source identities are preserved by the scientific audit and original scheduling records. Historical failures and dead stale-writer records are retained. Unexpected files cause refusal instead of silent omission. The one-byte admission/budget OS mutex sentinels stay at source and are listed as exclusions; they contain no experiment payload.

Required small COPY support includes the original plan, scalar/V1/V2 executors, tests, docs, audit/analysis files, this helper, audit support and validation proofs. All `evidence/v2/software/cuda_*.json` telemetry/proof reports are included. Additional pure-code dependencies listed in the auditor's `code_sha256` map are included. Original53 inputs, data and features are verified through the audit input map, then left to the original packager's existing inventory; they are not duplicated here.

## Terminal checks and capacity

An existing global `writer.lock` or per-fit `parallel_fit.lock` refuses inventory even if apparently stale. Every parallel generation needs a closed global lease and a terminal supervisor summary with matching amendment, plan and executor bindings. All authorized child PIDs must be proven dead or distinguishable by creation identity; their terminal leases and saved child summaries must match the closed supervisor record. Unknown/reserved launches and inaccessible live-process identity fail closed. A closed filename alone is insufficient. Unresolved historical crashes require explicit inspection and evidence; this tool never deletes a lock or invents a terminal state.

The original scalar's historical lease recorded only PID and plan SHA. Windows later reused its PID for an unrelated process. A narrow exception binds the pre-existing completed-boundary receipt `evidence/v2/audit_attempts/cuda_parallel_boundary_switch_20261018T072357896177Z.json`, pinned to SHA256 `842d48e5a39ebaffa9e27e397083d514ee3f1e2e739bf60d8601ab8c14de8a2b`. Its previous lease must equal the complete old two-field record, scalar PID must match and terminal confirmation must be exactly true. If that PID is alive now, its OS-reported Windows FILETIME creation identity must be strictly later than the receipt's explicit UTC terminal time. Comparison uses integer100ns ticks, without float rounding. Missing, altered or malformed receipt, unknown creation clock/token, or creation at/before that stop still refuses inventory. Generic worker/supervisor checks are unchanged; process names never establish identity and no process is killed or modified. A dead PID continues to pass normally. The valid matching receipt is included as exact COPY evidence and a separate SHA map even when the PID has subsequently exited, preserving inventory stability. Neither the old lease nor receipt is rewritten.

The inventory is deterministic and SHA-bound. It repeats history and terminal checks, then verifies every selected file again before returning. This narrows accidental concurrent changes but does not replace the maintainer's existing assertion that all source writers, including unrelated CPU/document writers, are stopped.

Execution evidence uses MOVE inside the same project, preserving relative paths and bytes: this adds zero logical payload bytes. Small support files use COPY. At the observed52-result snapshot, CUDA evidence occupied8,247,235 bytes across227 files; the90-result evidence estimate is about14–17 MB, before future unexpected failures or telemetry. This estimate is not a completion claim. The exact returned byte sums supersede it. The root-wide2,000,000,000-byte limit continues to include both historical V1 deliveries, runtime and all metadata. Existing packager metadata and reproduction reserves must be added to COPY bytes before assembly.

## Minimal parent-packager integration

1. After defining its `add` function, call `build_inventory(root)`, save the returned dictionary under `plan['cuda_delivery_inventory']`, and add every listed path with its returned action and origin `cuda90_closed_execution_inventory`. Do this before generic copy loops so duplicate support entries retain this origin. Original data/cache inventory is unchanged.
2. Extend `source_allowed` only for MOVE files under `evidence/v2/cuda_execution/` with this exact origin and the normal text extensions. This is a scope allowance; it must not replace exact inventory verification. Existing COPY scope already admits the small support files and needs a precise allowance for `tables/v2_cuda/descriptive_analysis.json`.
3. Call `verify_operations(root, plan)` before any package mutation, and require the saved inventory to match the newly built one in the assembly recheck. It requires exact CUDA operations, preserved paths, action/origin, SHA and byte size. Include all helper support in the delivered folder. The normal write-ahead ledger and final manifest then cover every CUDA MOVE/COPY alongside original576 assets.
4. After final-folder reproduction, preserve all CUDA files and audit/analysis as immutable. Run `build_inventory(delivery_root)` and compare its stable inventory with the saved plan when refreshing the final manifest. This helper writes no operational report that needs a refresh exception. The original four operational-report exceptions remain sufficient unless the parent separately decides to rerun the CUDA scientific auditor, which changes its timestamp and would require explicit narrowly bound refresh handling.

Synthetic tests: `python -B -m unittest discover -s code -p test_v2_cuda_delivery_inventory.py`. They use automatically removed temporary byte/lease fixtures and mocked liveness, never actual experiment scores or fits. Validation does not certify scientific adequacy, real GPU throughput or completion of CUDA90.
